Entendendo o MVC: A Hamburgueria 🍔

Para entender como o Model, View e Controller conversam, imagine o funcionamento de um restaurante. Clique nos personagens abaixo para descobrir quem é quem no mundo do código!

🍽️

View (A Visão)

O Cliente e o Cardápio

Na lanchonete: É a interface. É o que o cliente vê (o cardápio bonito, o prato montado). O cliente não entra na cozinha para fritar a carne.

No código: É o HTML/CSS (ou um JSON se for uma API). A View só exibe os dados bonitinhos na tela e captura os cliques do usuário.

🤵

Controller

O Garçom

Na lanchonete: O garçom anota o pedido (da View), leva para a cozinha (Model), pega o lanche pronto e entrega de volta para o cliente.

No código: É o "cérebro" das rotas. Ele recebe as requisições (ex: clicar no botão "Salvar"), pede pro Model buscar ou salvar no banco de dados, e depois decide qual View mostrar na tela.

🧑‍🍳

Model (O Modelo)

O Chef de Cozinha

Na lanchonete: O chef sabe a receita, vai no estoque pegar os ingredientes (Banco de Dados) e prepara o lanche com as regras corretas (não queimar a carne).

No código: É onde fica a Regra de Negócio e o acesso ao Banco de Dados. O Model não sabe de qual cor é o botão na tela, ele só sabe salvar, editar ou apagar dados.

O Trio MVC no Node.js

Como traduzimos isso para código de verdade? Em Node.js (com Express), nós separamos nosso projeto em pastas lógicas. Navegue pelas abas abaixo para ver como um sistema de "Cadastro de Usuários" funciona.

meu-projeto-node 
const UserModel = require('../models/userModel');

// O Controller (Garçom) gerenciando a requisição
const userController = {
  listarUsuarios: async (req, res) => {
    try {
      // 1. Pede pro Model os dados (Cozinha)
      const usuarios = await UserModel.buscarTodos();
      
      // 2. Entrega os dados para a View (Cliente)
      res.render('usuarios/index', { lista: usuarios });
      
    } catch (erro) {
      res.status(500).send("Erro ao buscar os usuários.");
    }
  }
};

module.exports = userController;
// Simulação de um banco de dados (A Cozinha / Estoque)
const dbUsuarios = [
  { id: 1, nome: 'Ana', curso: 'Desenvolvimento' },
  { id: 2, nome: 'Pedro', curso: 'Redes' }
];

const UserModel = {
  // Método focado apenas em DADOS. Sem HTML aqui!
  buscarTodos: async () => {
    // Em um app real, aqui teria uma query SQL ou MongoDB
    return dbUsuarios;
  }
};

module.exports = UserModel;

// O Menu da Lanchonete. Quem direciona os pedidos.

Por que dar esse trabalho todo?

No início, separar tudo em pastas parece "escrever código a mais à toa" (o chamado boilerplate). Porém, em sistemas corporativos, essa organização salva vidas.

✨

Separação de Preocupações (Separation of Concerns)

O front-end (quem cuida do HTML/View) pode trabalhar ao mesmo tempo que o back-end (quem cuida do banco/Model) sem dar conflito nos arquivos.

🛠️

Manutenção Descomplicada

Se o banco de dados mudar de MySQL para MongoDB, você altera apenas o Model. A View e o Controller nem ficam sabendo da mudança!

⚠️

Desvantagem: Complexidade Inicial

Para um app muito simples (ex: script de 1 página), usar MVC é matar formiga com canhão. Exige uma curva de aprendizado inicial.

Além do Básico

MVC e os Design Patterns

O MVC é um padrão arquitetural (define a estrutura geral). Dentro de suas camadas (Model, View, Controller), os programadores usam Padrões de Projeto (Design Patterns) para resolver mini-problemas específicos.

01. Criacionais

Factory & Singleton

Lidam com a criação segura de objetos.

  • ▶ Singleton: Garante que a conexão com o banco de dados (no Model) aconteça apenas uma vez, poupando memória do servidor.
  • ▶ Factory: Cria diferentes tipos de usuários (Admin, Aluno) sem espalhar vários "News" pelo Controller.
02. Estruturais

Adapter & Decorator

Organizam como as classes se compõem.

  • ▶ Adapter: Usado para "traduzir" dados de uma API externa para o formato que o seu sistema já espera.
  • ▶ Decorator: Adiciona funcionalidades extras em um objeto (ex: encriptar senha) antes de salvá-lo no Model.
03. Comportamentais

Observer & Strategy

Gerenciam o fluxo de informações e algoritmos.

  • ▶ Observer: "Avisa" automaticamente a View quando um dado no Model foi atualizado (muito comum em React/Vue).
  • ▶ Strategy: Permite ao Controller alternar táticas (ex: pagamento via Pix, Cartão ou Boleto) sem encher o código de `if/else`.
